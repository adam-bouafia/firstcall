FirstCall

The first responder for Kubernetes incidents. It watches a cluster and, when a workload breaks, collects the evidence an on-call engineer gathers in the first 15 minutes. It also checks what changed in the last rollout, asks an open-weight language model for a diagnosis, and confirms it with read-only commands. It posts the result where the team already looks: Kubernetes Events, Prometheus, Grafana, and a Telegram alert with buttons (24/7, or only nights and weekends). It proposes a one-click fix that a person approves after a server dry run, then verifies the cluster is healthy again.

Safety model

It investigates on its own. It fixes only with your approval.

A read-only command only looks at the cluster and can't change it. FirstCall runs those by itself to gather evidence. A fix is only ever proposed: one narrow command, checked by a server dry run, applied after a named person approves it.

Runs on its ownOnly after approval + dry runNever
kubectl get · describe · logs · top · eventsrollout undo · set image · set resourcesdelete · exec · drain · edit
rollout status · auth can-iscale · patch (Deployment/Service only)Secrets · RBAC · kube-system

Independent locks. In code: allow-lists for read-only commands and for fixes, with no pipes, chaining or redirection. Before a fix: a server-side dry run, and approval of that exact command (hash-checked). In Kubernetes: read-only RBAC with no Secrets and no exec. Write verbs for fixes are only granted per namespace, and only when remediation is enabled. Even if the code had a bug, the cluster would refuse anything else.

Design decisions

Why it is built this way

Open-weight models

Logs contain customer data and secrets. With open weights the same model can run through a hosted API today and inside the company's own infrastructure tomorrow, with no vendor lock-in.

Rejected: a closed-model API (a compliance blocker for regulated teams).

Curated snapshot, one call

The collector gathers what a senior engineer checks first, so the model reasons over ~1,000 tokens. Cost and latency are predictable, and even small models perform well.

Rejected: a free-roaming tool-calling agent (unreliable on small models, and cost has no ceiling).

Humans approve, machines investigate

Read-only commands run automatically. A fix is one allow-listed command, dry-run by Kubernetes, then applied only after a named person approves it. One wrong delete would end trust in the tool.

Rejected: autonomous remediation, or a free-form "run anything" button.

Ask "what changed?" first

Most incidents follow a change. FirstCall diffs the last two rollout revisions (image, env var names, resources, probes, command) and gives that to the model as evidence, so it can propose a precise rollout undo.

Rejected: diagnosing from the current state only.

Page only when nobody is watching

Telegram alerts with buttons: Investigate runs the read-only next command from a phone. Two modes: 24/7, or nights and weekends only (weekdays 17:00–09:00), switchable at runtime. The console and Events are never muted.

Rejected: pushing every alert during office hours (alert fatigue).

Cascade routing

A small mixture-of-experts model handles common failures and escalates to a large model only when unsure. You pay big-model prices only for hard cases.

Rejected: always using the biggest model.

k3s vs kind

Right cluster for each job

kind runs each node as a container inside Docker. k3s is one process on the host with containerd built in. So: k3s for the long-running local cluster, kind for disposable CI clusters.

CI/CD

Every change is proven on a real cluster

Build and end-to-end test

Tests, UI build and helm lint run first. Then a kind cluster starts, both images are built, the chart is installed and 8 workloads are broken on purpose. The test asserts detection, diagnosis, Events, Alertmanager handling and resolution. Images, and on release the Helm chart, are published to a registry.

Model benchmark as a gate

Every change to the prompt, collector or model list re-runs the benchmark against ground truth for 8 failure classes. It scores each model, the cascade and a rules-only floor, and fails the build if quality drops.

Compared with k8sgpt

k8sgpt explains what looks wrong. FirstCall works the incident.

k8sgpt is a CNCF Sandbox project and broader in scope. The benchmark runs both on the same cluster with the same model, and scores both against the same ground truth.

Seen on the test cluster: for payments-api, k8sgpt reports "termination reason Error exitCode=1". The log line naming the missing DATABASE_URL never reaches it, because logs aren't in its default analyzers.
