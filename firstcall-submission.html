FirstCall

The first responder for Kubernetes incidents. It watches a cluster, and when a workload breaks it gathers the evidence an on-call engineer gathers in the first 15 minutes, works out what changed, and asks an open-weight model on Nebius Token Factory for a diagnosis it must back with quotes. It confirms with read-only commands, then proposes one fix that a human approves. Detect to fix, in under a minute, for a fraction of a cent.

The problem

A small platform team runs the cluster. When a workload breaks, the first 15 minutes are always the same: describe, logs --previous, events, "what did we deploy?". Junior on-call engineers escalate because they don't know the next command. And pasting production logs into a closed AI chat is not allowed: they contain customer data and secrets.

Why now

Open-weight models only recently became good enough at structured operations reasoning, and Token Factory serves them at cents per thousand incidents, so this can run on every alert instead of being a chatbot someone remembers to open. The same weights can later run inside the customer's own network, which a closed model can never offer.

Architecture

Nebius Token Factory is the engine

One OpenAI-compatible client, a model registry in models.yaml, and a cascade router. Everything else is standard Kubernetes plumbing, so a platform team can adopt it in an afternoon.

Models on Token Factory

Qwen/Qwen3-30B-A3B-Instruct-2507 for the first pass (3B active parameters: fast and cheap enough for every alert), Qwen/Qwen3-235B-A22B-Instruct-2507 for hard cases, openai/gpt-oss-120b and nvidia/NVIDIA-Nemotron-3-Nano-30B-A3B compared in the benchmark.

Cascade routing: the small model answers; if it is unsure (confidence < 0.75 or category Other), the same snapshot goes to the large model. Quality of the big model, cost close to the small one.

Why this is not a chatbot

The collector builds a curated snapshot (~1,500 tokens): pod spec with env var names only, container states, events, current and previous logs, metrics, Services, PVCs, nodes, and a diff of the last rollout. One structured call answers with quoted evidence, a next command and a proposed fix. Cost and latency are predictable; nothing is left to a free-running agent.

Tavily is used only when the model is unsure: the sanitized error string is searched, and the second answer must cite the URLs.

Against a rules baseline

A keyword runbook with no model is the floor in the table. It misses the failures with no error text, such as a Service whose selector no longer matches its pods.

Against k8sgpt

The CNCF Sandbox project, run on the same cluster with the same Token Factory model. It reports "termination reason Error exitCode=1" for our crash-loop; the log line naming the missing variable never reaches it, because logs are not in its default analyzers.

Against closed models

The same 8 scenarios through GPT and Claude. That is the number that matters for the "open model advantage": equal quality at a fraction of the price, with the option to self-host.

Who pays

Platform teams of 2–15 engineers at European scale-ups, and managed service providers who run many clusters and bill for on-call. The MSP channel is the fastest route: one integration, dozens of clusters.

Why we win

Sovereignty (open weights, self-hostable, redaction before inference), price (fractions of a cent), and fit (Helm chart, Prometheus, Alertmanager, Kubernetes Events: no new system to adopt). Incumbents are either dashboards without diagnosis, or closed-model assistants that regulated teams cannot use.

Data minimisation

Environment variable values are never collected and the ServiceAccount cannot read Secrets. Everything sent is scrubbed of keys, tokens, credentials, emails and IPs, and the count is shown in the UI. Web search only ever sees a sanitized error string.

Honest uncertainty

Every answer carries a confidence score and quoted evidence, may say Other, and escalates instead of guessing. Engineers mark answers correct or wrong, which is the training set for later.

Auditability

Every diagnosis, command, notification and approved fix is in the incident timeline, in Prometheus, and as a Kubernetes Event on the workload itself.
